# 火焰图采样器使用指南 🔥

## 一、基本使用

### 1. 开始采样

```objc
// 建议采样间隔：50-100ms（平衡性能和精度）
[[SUPSimpleFlameGraph sharedInstance] startSamplingWithInterval:0.05]; // 50ms

// 执行你要分析的代码...
[self performHeavyTask];

// 停止采样
[[SUPSimpleFlameGraph sharedInstance] stopSampling];
```

### 2. 查看详细统计（控制台）

```objc
// 在控制台输出 Top 20 热点，包含具体 ms 数值
[[SUPSimpleFlameGraph sharedInstance] printDetailedStatistics];
```

**输出示例：**
```
========== 📊 火焰图详细统计 ==========
总采样次数: 100
采样间隔: 50.00 ms
总耗时估算: 5000.00 ms

调用路径                                                              采样次数       耗时(ms)     占比(%)
========================================================================================================
main;viewDidLoad;fetchData;networkRequest                                 40       2000.00     40.00%
main;viewDidLoad;setupUI;layoutViews                                      20       1000.00     20.00%
main;applicationDidLoad;initDatabase                                      10        500.00     10.00%
...
========== END ==========
```

### 3. 导出到 speedscope（可视化）

```objc
// 导出带时间信息的火焰图数据
[[SUPSimpleFlameGraph sharedInstance] printFoldedStackToConsole];

// 复制控制台输出的内容，粘贴到 https://speedscope.app
```

**导出格式示例：**
```
# Total Samples: 100
# Sampling Interval: 50.00 ms
# Total Time: 5000.00 ms
# ----------------------------------------
main;viewDidLoad;fetchData;networkRequest 40  # 2000.00 ms
main;viewDidLoad;setupUI;layoutViews 20  # 1000.00 ms
...
```

## 二、完整示例

```objc
@implementation MyViewController

- (void)profilePerformance {
    // 1. 开始采样（50ms 间隔）
    [[SUPSimpleFlameGraph sharedInstance] startSamplingWithInterval:0.05];
    
    // 2. 执行要分析的代码
    [self loadDataAndUpdateUI];
    
    // 3. 停止采样
    [[SUPSimpleFlameGraph sharedInstance] stopSampling];
    
    // 4. 查看详细统计
    [[SUPSimpleFlameGraph sharedInstance] printDetailedStatistics];
    
    // 5. 导出火焰图（用于 speedscope）
    [[SUPSimpleFlameGraph sharedInstance] printFoldedStackToConsole];
}

- (void)loadDataAndUpdateUI {
    // 模拟耗时操作
    [self fetchDataFromNetwork];
    [self parseJSON];
    [self updateTableView];
}

@end
```

## 三、采样间隔建议

| 场景 | 采样间隔 | 说明 |
|------|---------|------|
| 开发调试 | 10-20ms | 高精度，捕捉细节 |
| **性能分析（推荐）** | **50-100ms** | **平衡精度和性能** ⭐ |
| 生产监控 | 100-500ms | 低开销，长时间监控 |
| UI卡顿检测 | 16.67ms | 一帧时间（60fps） |

## 四、数据解读

### 控制台统计

- **采样次数**：函数被采样到的次数（次数越多 = 耗时越长）
- **耗时(ms)**：估算的实际耗时（采样次数 × 采样间隔）
- **占比(%)**：该函数占总耗时的百分比

### speedscope 火焰图

1. 打开 https://speedscope.app
2. 粘贴控制台输出的数据
3. 选择 "Left Heavy" 视图查看完整调用栈
4. 鼠标悬停可以看到具体的 ms 数值（在注释中）

**火焰图解读：**
- 最宽的条 = 最耗时的函数
- 从下往上看：调用链路（底部是根函数）
- 颜色无特殊含义，只是为了区分

## 五、优化示例

### 发现问题

```
调用路径                                    采样次数    耗时(ms)    占比(%)
viewDidLoad;fetchData;networkRequest           40       2000.00    80.00%
viewDidLoad;setupUI                             5        250.00    10.00%
```

**分析：**
- `networkRequest` 占用 80% 时间，是主要瓶颈
- `setupUI` 只占 10%，已经很快

### 优化方向

1. **优化 networkRequest**（80% 时间）
   - 异步请求，不阻塞主线程
   - 添加缓存机制
   - 使用 CDN 加速

2. **不要优化 setupUI**（10% 时间）
   - 已经很快，优化收益小

## 六、注意事项

⚠️ **采样会暂停主线程** (thread_suspend)，虽然时间很短（微秒级），但频繁采样仍有性能影响

✅ **最佳实践：**
- 仅在开发/测试环境使用
- 采样时长建议 5-10 秒
- 采样间隔不要低于 10ms（除非特殊需求）
- 生产环境需要更低的采样频率（100ms+）

## 七、常见问题

### Q: 为什么 speedscope 显示的还是百分比？

A: speedscope 默认显示百分比，但鼠标悬停时可以看到具体数值。新版本的导出在注释中包含了 ms 信息：

```
main;viewDidLoad 40  # 2000.00 ms
```

### Q: 如何只看 Top 10 热点？

A: `printDetailedStatistics` 默认显示 Top 20，已经按耗时排序。

### Q: 可以采样子线程吗？

A: 当前版本只支持主线程。如需子线程采样，需要修改 `captureCallStackOfThread` 方法。

## 八、技术原理

1. **定时采样**：每隔 N ms 采样一次主线程
2. **获取调用栈**：读取 CPU 寄存器（PC/LR/FP）+ 栈回溯
3. **符号化**：地址 → 函数名（dladdr）
4. **聚合**：构建调用树，累计采样次数
5. **计算时间**：采样次数 × 采样间隔 = 估算耗时
